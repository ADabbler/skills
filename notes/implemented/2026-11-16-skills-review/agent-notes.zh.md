# Agent Notes 中文对照

英文技能主文件及全部参考内容的中文对照。实际使用的技能保持英文。

技能描述：创建并维护项目工作笔记和决策记录，用于任务延续和交接；在工作推进、任务完成或决定变化时，审查、合并、清理或归档相关笔记。

界面短描述：创建并维护工作笔记与决策记录。

## 技能主文件

英文原文：[SKILL.md](../../../skills/agent-notes/SKILL.md)。

只保留必要的项目上下文，让后续会话无需查阅原始讨论即可恢复工作或理解决定。围绕具体主题组织笔记，并保持内容有效。

### 判断记录什么

阅读适用的项目指令和笔记约定，在创建文件前找到已有笔记目录。工作范围遵循用户任务。审查任务报告发现；获得修改授权的维护任务才应用修改。

用户要求记录，或保留上下文有助于继续、审查或交接工作时，记录笔记。先搜索相关笔记和项目文档。同一主题的工作推进时，更新相关笔记。没有合适记录时创建笔记；替换已生效决定或其决定性理由时，另建记录。保留代码、测试和现有文档没有解释的长期理由或约束。机械修改和显而易见的局部修复，本身不足以构成独立笔记的理由。

笔记与代码不一致时，先判断是笔记过时、实现违反已约定的决定，还是决定已经改变，再依据证据纠正相应内容。

### 恢复与推进工作

开始相关工作时，搜索活动笔记，恢复目标、已约定范围、约束、发现、当前进度、阻塞和下一步。对可能变化的事实，核对相关实现和证据。历史问题再查归档。可在已有笔记目录中使用类似命令检索：

```sh
rg --hidden --no-ignore --glob '!archived/**' 'mechanism-or-topic' .
```

有重要发现或进展后，以及交接前，更新相关笔记。区分事实、假设、待选事项和已确认决定。替换过时的工作上下文，不积累会话流水账，并链接相关文件和证据。

任务完成、新增或替换决定，以及证据改变已记录的前提时，检查本任务影响的笔记，不等待单独的清理请求。

### 路径与内容组织

使用项目已有笔记目录；没有时，使用项目根目录下的 `.agents/notes/`。

- 使用 `proposed/`、`implemented/`、`rejected/`、`archived/`，有对应记录时才创建目录。
- 初始采用平铺结构。只有检索需要时才增加一层稳定分类，各生命周期目录使用一致的分类名称。
- 文件名使用 `YYYY-MM-DD-topic.md`，包含首次提出日期和简短英文主题；编辑、移动时保留该日期。补录已有决定但无法确认原日期时，使用记录日期，并说明这是补录日期。
- 优先使用单个文件。需要单独管理审查或证据时，使用带日期的主题目录，包含 `index.md`，并按需增加 `review.md` 和 `evidence/`；整组记录的状态写在 `index.md` 中。
- 笔记语言遵循用户要求，否则使用交流语言。目录名和状态值使用英文。
- 笔记根目录下的 `README.md` 在有帮助时记录项目特有约定和入口。是否纳入版本控制，遵循项目约定。

创建、重组或审查笔记时，读取下文的“笔记写作指导”。拿不准是否创建或保留时，参考“判断示例”。

### 维护与审查

审查受影响笔记、选择或变更状态、处理取代关系、合并、清理或归档时，读取[生命周期规则](#生命周期与保留)。记录提案并不授权实现提案。移动、删除和外部验证遵循任务权限；需要额外授权的待办操作应明确报告。

核对事实、状态、路径、已记录备选，以及相关覆盖或验证缺口。公共文档和必要构建流程不能依赖私有笔记才能使用。

编辑后简要报告修改、未解决问题和实际运行的检查。区分静态检查与行为验证。

文字编辑可在 `prose-standard` 可用时配合使用。

## 生命周期与保留

英文原文：[lifecycle.md](../../../skills/agent-notes/references/lifecycle.md)。

### 整理判断

对每篇受影响的笔记，判断哪些内容仍有用、应放在哪里、状态是否符合实际。移除活动笔记中已经失去用途的过程文字。

### 状态

| 目录 | 进入条件 |
| --- | --- |
| `proposed` | 调查、规划、实现中或延后的工作 |
| `implemented` | 已采用，必需的验收检查完成，且仍有维护价值 |
| `rejected` | 未采用，但否决理由仍能防止合理可预见的错误 |
| `archived` | 曾经落地，保留历史价值，但已不再指导当前工作 |

有阻塞性验收缺口时，笔记继续保留为 `proposed`；明确接受的非阻塞验证缺口可以保留在 `implemented` 中。验收要求遵循已约定的任务范围。

### 状态流转与记录整理

| 情况 | 处理方式 |
| --- | --- |
| 补录已有决定 | 核实后直接记录到 `implemented`；无法确认的历史动机明确标为未知 |
| 完成调查 | 继续工作则形成提案；否则只在调查结论有助于后续工作时将其记入相关笔记，并清理失去用途的材料。调查结束本身不等于方案已实现 |
| 完成提案 | 移至 `implemented`，改写为当前行为，移除执行清单和已解决发现，保留有用证据、限制和覆盖缺口 |
| 延后工作 | 留在 `proposed`，说明原因和重新考虑的条件 |
| 拒绝或放弃方案 | 理由能防止重犯时移入 `rejected`，否则清理 |
| 事实改变、决定未变 | 原地更新路径、名称等事实 |
| 修订讨论中的提案 | 原地更新当前选择及理由 |
| 替换当前有效决定或其决定性理由 | 创建新提案并与当前笔记互链；替代决定生效前，原决定仍然有效 |
| 部分取代 | 原笔记收窄到仍有效的决定和理由，两篇互相链接 |
| 完全取代 | 在相关活动笔记中保留当前工作仍需要的内容；旧记录的独立历史价值值得保存时归档，否则清理 |
| 完整合并 | 保留每项独有且有用的信息，再移除重复记录 |
| 重新考虑否决方案 | 创建引用原否决记录的提案，说明哪些前提改变了 |
| 重新引入归档方案 | 创建当前 Agent Note，引用历史证据 |

主题目录作为整体移动。完成工作时，将保留的非阻塞发现合入主笔记，移除失去用途的辅助材料。移动或删除笔记时，更新当前项目文件中指向它的引用：说明当前行为的链接应指向当前解释，Agent Notes 中的历史引用可以指向归档。移动活动笔记时，修复笔记内部受影响的相对链接。

### 保留判断

按后续工作的用途判断是否保留。

工作进行期间，发现、进度和开放问题可以仅为了任务延续而暂存。完成后，按后续工作需要将结论保留在相关笔记中，清理已经完成工作用途的材料。项目文档说明当前实现；历史背景有保留价值时，可以留在笔记中。

合并、归档或清理笔记前，核对其中仍相关的决定、理由、适用条件、职责和资源管理规则、明确保证不发生或不支持的行为、证据、覆盖缺口，以及重新引入条件。将仍指导当前工作的内容连同来源和验证范围保留在相关活动笔记中。

机械记录、完全重复的内容，以及已不能防止合理可预见错误的否决记录，可以清理。

### 归档

只有已经实现、已不再指导当前工作、但仍有独立历史价值的决定才归档。保留 `Status: implemented`，添加 `Archived: YYYY-MM-DD`，连同证据移动。归档正文和证据保持不变。

默认检索排除归档。发现事实错误时，在当前 Agent Note 中引用历史快照并纠正。明确的清理任务可以删除已经失去价值的归档。

## 笔记写作指导

英文原文：[writing-guide.md](../../../skills/agent-notes/references/writing-guide.md)。

面向下一位恢复任务或重访决定的人。使用能保留必要信息的最短形式。章节与顺序按实际主题选择；简单笔记可能只需要状态行和几个段落，复杂计划可以按问题、组件或执行顺序分节。除项目规定外，不要求固定章节或备选数量。

### 基本信息

主笔记标识主题和生命周期状态：

```markdown
# 主题

Status: proposed
```

根据[生命周期规则](#生命周期与保留)使用 `proposed`、`implemented` 或 `rejected`。归档笔记保留 `Status: implemented`，另加 `Archived: YYYY-MM-DD`。文件名或主题目录使用首次提出日期；补录决定且原日期未知时，使用明确注明的记录日期。`Archived` 表示归档时间。

### 按记录目的选择内容

一篇笔记可以同时包含调查发现、提案和审查结果。事实与解释放在一起，已有背景使用链接，不重复解释。只选择与工作相关的指导，下列类别不是待填模板。

#### 调查

说明问题、范围，以及什么证据足以完成调查。区分已验证发现、假设和开放问题；来源靠近相关结论。按恢复工作的需要，保留当前位置、已完成检查、阻塞、相关文件和下一步。概括证据，不粘贴搜索输出或探索流水账。

#### 提案

问题应脱离所提方案也能成立。说明具体选择、决定性理由、有意义的成本与风险，以及可观察的完成条件。区分已批准决定和待选事项，按需保留当前进度和下一步。

比较有助于解释选择时，记录确实考虑过的备选，写出它们最强的相关论据和采用或拒绝的理由。没有备选时省略该节，不编造选项。

#### 已落地

说明解决的问题、当前决定、机制、范围和不易直接看出的理由。按维护价值保留收益、成本、限制、相关备选、证据、已接受的非阻塞覆盖或验证缺口，以及重新考虑条件。必要行为在本地写清，扩展实现细节链接相关源文件或文档。

#### 已否决

指明提案、决定性的反对理由和使其不适用的条件。现行替代或重新考虑条件，仅在已知且有助于防止重复讨论时记录。

#### 审查

每项未解决发现说明缺陷、位置、影响和证据，建议应可操作。短段落通常足够。移除已解决发现前，将仍有用的结论和证据合入相关正文。

### 证据

概括检查对象、方法、结果和未覆盖范围；版本或环境影响解读时一并记录。持久证据使用链接，临时证据作概括。区分已完成检查与计划或待执行的检查，说明证据来自源码检查、模拟还是真实执行。不要在进度、验收和验证章节重复相同结果。

### 简短调查示例

以下虚构示例展示精简的交接记录。

```markdown
# 导出失败调查

Status: proposed

目标：确认导出失败是否会损坏已有文件，覆盖单个导出和批量导出。

已确认：src/export.ts 的 writeExport 在校验全部字段前打开目标文件。本地复现中，单个导出遇到非法字段后失败，并使已有目标文件变为空文件。

开放问题：批量导出是否使用同一写入路径？目前只复现了单个导出。

下一步：检查 src/batch-export.ts，再决定校验应放在哪里。
```

源码位置和观察结果支持该发现，开放问题限定其适用范围；目标和下一步足以让另一会话继续调查。几个段落即可完成这项记录。

## 判断示例

英文原文：[examples.md](../../../skills/agent-notes/references/examples.md)。

以下场景用于判断一篇笔记或一段文字的价值。关键是这些信息能帮助后续工作或决定什么。

### 记录工作上下文与理由

| 场景 | 判断与处理 |
| --- | --- |
| 比较了两个候选库，但许可证兼容性未解决 | 在 `proposed` 中保留比较、来源、开放问题和下一项检查 |
| 实现中断，部分检查已通过 | 更新当前进度、剩余检查、阻塞和相关文件链接，以便继续工作 |
| 修复一处局部条件，回归测试已清楚表达行为 | 没有额外长期理由，无需独立笔记 |
| 任务完成，留下长调查日志，但只有一项约束仍有用 | 在相关笔记中保留约束、理由和证据，移除已解决的探索内容和完成清单 |
| 为满足接收系统的文档要求选择导出编码 | 改动虽小，但约束不明显：将要求和来源写入相关已有笔记，必要时创建新笔记 |
| 为隔离全局状态，每个集成测试单独进程运行，导致耗时增加 | 记录隔离要求和运行成本，防止未来优化测试时破坏必要隔离 |
| 取消后台任务后留下临时文件，由另一个组件清理 | 记录谁请求取消、谁负责删文件、何时清理完成 |

### 保留有用结论

| 场景 | 判断与处理 |
| --- | --- |
| 调查排除了依赖缺陷，并找到了受支持的配置 | 结论有助于后续工作时，将其和支持证据保留在相关笔记中；清理已完成用途的调查材料 |
| 存储方案改变，旧笔记还包含仍适用的备份要求 | 按需更新或创建相关决策笔记，保留仍约束系统的备份要求 |
| 已完成决定不再指导当前工作，但其历史权衡仍有独立价值 | 在相关主题收尾检查时归档，保留正文，修复活动材料中指向它的链接 |
| 某库因仍有效的约束在比较中落选 | 将比较留在所选设计的笔记中；只有独立记录能防止反复讨论时才另建否决记录 |
| 两年前的否决说明付款超时后重试会重复扣款，因为接口不支持幂等 | 限制仍存在时保留，它仍能防止合理可预见的错误 |
| 接口已经支持幂等键，采用的重试设计也覆盖剩余约束 | 否决前提已过时，有用内容已被当前记录覆盖，可以清理 |
